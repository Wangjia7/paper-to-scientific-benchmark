# 04 — 标准化平台字段：公开目标与私有验算严格分层

## A. 想法设计（公开给 Agent）

| 字段 | 需写什么 | 常见问题 |
|---|---|---|
| 标题（5–30 字） | 科学对象＋核心操作＋结论，例如“三重盲校准” | 冗长、空泛、纯工具名 |
| 领域/方向 | 授权范围内的领域及联动方向；**首次锁定** | 反复换领域 |
| 关键词（3–15 个，单项 1–20 字） | 对象、机制、方法、输出/验收指标 | 只有工具没有科学问题 |
| 任务问题（50–20000 字） | 按「统一科学问题与给定输入 → 平台要求的可证伪判断 → 必须提交的结果 → 精确公开评分规则」组织；允许共享一套实验 | 把关键步骤/最佳模型作为命令写出；未给评分条件 |
| 任务价值（50–20000 字） | 为什么科学问题真实、不同解释为何竞争、哪个判断需要专家能力、各自如何可证伪 | 把耗时/代码复杂当科学难度 |
| 软件/工具（≤2000 字） | Linux CLI，Python等具体版本及开源替代 | 私有/付费/GUI/GPU 强依赖 |
| 硬件 | 明确无需特殊设备 | 依赖高端 GPU |
| 运行时长 | 确认全部操作≤5h；报告“实测参考运行”与“Agent预算”区别 | 只统计跑脚本时间 |

公开任务问题必须让 Agent 知道「**要得到什么物理量**」，而不是「**如何做出它**」；其中可以定义客观的物理量、参考红移、单位和实验约定，这不等于泄漏求解路径。

## B. 任务配置（公开数据、私有验证）

| 字段 | 需要的证据 |
|---|---|
| Agent 输入数据 | 可直接下载的公开集 URL 或可用的 ZIP；必须真实存在且能在 Linux 离线/可网络条件运行 |
| 数据使用范围与读取 | 文件关系、列/单位、缺测值、校准/盲测划分、随机性与真实/合成性质 |
| 关键步骤（仅评审） | 参考可行求解路径、必要超参数、可识别性检验、弱基线与最关键中间校验；**绝不复制至公开题面** |
| 预期输出及格式 | 明确每项文件名、字段、主键、单位、行数和浮点精度约定 |
| 正确性判定规则 | 唯一统计量、权重、分组、容差、边界、输入有效性、子任务及总分门槛；与公开题面完全一致 |

如含“上传参考论文”：论文附件不自动等于可执行数据。要确认 paper Data availability 是否提供全部需要的逐对象观测。没有就上传精简公开数据或构建明确标为合成的实验，不得假装复现原实测目录。

## 提交文件构成（建议）

```text
submission/
├── task_submission.md         # 可粘贴各字段，含 A/B 标记
├── public/
│   ├── README_AGENT.md         # 公开数据说明与评分规则
│   ├── input_data.zip          # 仅公开输入
│   └── templates/              # 预测格式模板
├── private/
│   ├── manifest.json           # 私有清单，含评分真值路径
│   ├── truth/                  # 隐藏真值，可为多个判断共用一个表
│   ├── simulator/              # 固定种子生成器
│   ├── baseline/               # 不读取真值的参考求解器
│   └── grade.py                 # 按公开规则独立评分
└── reports/
    │   ├── independence_review.md # 科学判断可证伪、独立失分及内在联系
    ├── smoke_test.log          # 公私两环境可运行证据
    └── checklist.md            # 已完成/未完成/已知风险
```

若平台只提供一个评分 ZIP 入口，打包 `private/`；保证评分环境可读取真值而 Agent 环境不可能读取。平台文件路径按实际系统调整，所有路径必须用真实文件存在性检查验证。

## 审核停机线

- 未达到当前平台要求的可证伪科学判断数量（如本对话评审要求三项）：**不许进入工程实现**。注意**不要求三套独立受控实验**，共享数据只需证明识别和评分独立。
- 公共题面尚无唯一评分契约：**不许上传评审**。
- 数据路径是想象的、隐藏真值在公共 ZIP、生成器不可重跑：**不得宣称可复现**。
- 强/弱基线未测试：**不得宣称难度合适**。
