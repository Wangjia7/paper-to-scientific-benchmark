# 12 — Release Lock：题面—ZIP—私有真值—评分器一致性（强制 Gate 6c）

## 核心故障：FP V4 题面与 V1 数据错配

网页要求 A/B/C 三个科学判断（40/30/24 盲预测），公开数据却是仅 4 文件的 `fp_selection_response_v1`，题目只有 `fp_fit.json, response.csv, size_bias.csv`，没有 V4 视场、仪器、校准标签。V1 生成器即使复现 100% 也只会复现 V1，**不能证明 V4 可解**。这不是论文的科研难度问题，应该进行**附件替换/版本发布**，不应改动已经认可的科学题目以迁就旧附件。

## 发布单元与不可变标识

每个版本必须把以下对象视作一个可复验的原子发布单元：

1. `task_idea_public.md`（公开科学目标与评分合同），与正在提交的平台字段逐字或逐契约同义。
2. `agent_input.zip`（公开 README、输入 schema、必要可见校准/盲测数据、输出模板、文件 SHA-256 清单）。
3. `hidden_scoring.zip`（私有真值、确定性生成器/冻结 seed、仅 public 的 reference_solver、独立 grader、消融、QA 与实际日志）。
4. `release-lock.json`（对应发布单元：release_id、schema_version、预期成员列表与数量、科学判断及输出行数、必要 QA）。
5. `audit_results.json`（实际执行命令、CPU/峰值内存、哈希、严格与等价输入、科学基线结果）。

发布前不能混用版本、从旧 ZIP 随机复制成员或仅更新外部文案。每次重大科学对象变更需要重新生成该发布单元，保留上一版供问题复现。

## 阶段门槛

- **题目设计阶段**：提交标题、领域、统一科学问题、科学判断、价值、运行限制，确保设计对应**真实可构建**的数据。平台未开放任务配置，不声称已提交或审核附件。
- **任务配置阶段**：必须实际上传 `agent_input.zip` 与符合平台入口权限的私有评阅材料。**不要把 hidden_scoring.zip 上传 Agent 可见附件**。
- **复审阶段**：以平台实际拿到的 ZIP 和字段为准，而不是本机最新文件。下载/复核平台附件版本、大小、文件成员、SHA-256，再执行公私双环境评分。
- **平台通过**：明确是题目设计通过、配置通过、仅用户报告通过还是评审专家独立质量通过。不能把某次成功扩展到所有关卡。

## 自动检查与人工边界

`scripts/release_lock.py` 根据冻结合同检查 ZIP 成员集合、内部 public manifest、成员字节数和 SHA、release ID、私有必需脚本/真值、输出模板物理行数与规范 ID，以及题面中必要的版本/输出字段。应当运行正反两组验证：`V4_PUBLIC + V4_PRIVATE => PASS`、`V1_PUBLIC + V4_PRIVATE => FAIL`，并测试漏文件、追加无关文件、篡改单个成员和泄漏真值。

还需要**独立运行私有原始 generator**比较结果；仅检查哈希不能证明生成器能复现。还要用仅公开数据运行参考求解器。Release Lock 不检查科研难度、科学真值是否合理或跨模拟域泛化。

## 常见误判

- “我已经在本地有正确的 V4 文件”不能推出平台实际收到 V4；文件交付必须回读检查。
- “生成器可以确定性再生”不能保证它再生的是当前版本。
- “公私都有相同的 release_id”仍可能发生内部某个数据文件旧版；必须核对成员字节哈希/行数与真值 ID 映射。
- “参考解得 95.2 分”只证明该参考解与某一真值-评分器组合一致，**不**证明平台执行的是这一组合。
- “私有评分包存在”不等于评审能访问；必须提供正确的评阅入口和实际 CLI 日志。
